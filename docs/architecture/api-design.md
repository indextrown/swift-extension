## 공개 범위를 최소로 유지해요

- 기본 접근 수준은 `internal`이에요. 외부에서 쓸 이유를 설명할 수 있을 때만 `public`으로 올려요.
- 저장 프로퍼티는 공개하지 않아요. 내부 표현을 바꿀 여지를 남기기 위해 읽기 전용 연산 프로퍼티나 메서드로 노출해요.
- 클래스를 공개할 때는 상속을 열 이유가 없으면 `public final class`로 적어요. `open`은 상속을 전제로 설계한 타입에만 써요.
- 타입 전체를 공개하기 전에 "이 타입을 쓰는 쪽이 무엇을 할 수 있어야 하는가"를 먼저 적어요. 그 목록에 없는 멤버는 공개하지 않아요.

```swift
// Preferred: 내부 표현은 감추고 필요한 동작만 공개해요.
public struct Stack<Element> {
    private var storage: [Element]

    public var isEmpty: Bool { self.storage.isEmpty }
}

// Avoid: 내부 표현을 공개하면 배열을 다른 버퍼로 바꿀 수 없어요.
public struct Stack<Element> {
    public var storage: [Element]
}
```

## 표준 라이브러리의 이름을 따라가요

쓰는 사람이 이미 아는 이름을 쓰면 문서를 읽지 않아도 동작을 예상할 수 있어요. [Swift API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/)를 기준으로 삼고, 같은 의미의 표준 라이브러리 이름이 있으면 그 이름을 그대로 써요.

| 하려는 일 | 사용할 이름 | 피할 이름 |
| --- | --- | --- |
| 비어 있는지 확인 | `isEmpty` | `empty()`, `hasNoElements` |
| 요소 개수 | `count` | `size`, `length` |
| 마지막 요소 제거 | `removeLast()`, `popLast()` | `pop()`만 단독으로 |
| 용량 미리 확보 | `reserveCapacity(_:)` | `prepare(capacity:)` |

- 부수 효과가 있는 메서드는 동사로(`push(_:)`, `removeAll()`), 값을 돌려주기만 하는 멤버는 명사로(`top`, `count`) 이름 붙여요.
- 변경형과 비변경형이 쌍으로 있으면 `sort()`/`sorted()`처럼 표준 라이브러리의 활용형 규칙을 따라요.
- 매개변수가 없고 부수 효과가 없으며 O(1)로 계산되면 메서드 대신 연산 프로퍼티로 만들어요.
- 요소를 제거하면서 돌려주는 연산은 비어 있을 때의 동작이 이름에서 드러나야 해요. 옵셔널을 돌려주면 `popLast()`처럼, 비어 있으면 실패로 처리하면 `removeLast()`처럼 이름 붙여요.

## 값 타입을 기본으로 삼아요

- 자료구조는 `struct`로 만들어요. 복사한 값이 서로 영향을 주지 않는 값 의미론을 유지해요.
- 내부에서 참조 타입 버퍼를 쓰더라도 쓰는 쪽에서는 값 의미론으로 보여야 해요. 복사 시점 관리는 [성능 기준](performance.md)의 CoW 항목을 따라요.
- 참조 의미론이 꼭 필요한 경우(공유 캐시, 뷰 등)에만 `class`를 쓰고, 그 이유를 문서 주석에 적어요.

## 표준 프로토콜 채택

쓸 수 있는 표준 프로토콜을 채택하면 `for-in`, `map`, 리터럴 초기화 같은 기능을 그대로 얻을 수 있어요.

| 프로토콜 | 채택 기준 |
| --- | --- |
| `Sequence`, `Collection` | 요소를 순회하는 자료구조라면 채택해요. 순회 순서를 문서 주석에 적어요. |
| `ExpressibleByArrayLiteral` | 리터럴로 만드는 것이 자연스러운 컨테이너에 채택해요. |
| `Equatable`, `Hashable` | 요소가 해당 프로토콜을 만족할 때만 성립하도록 조건부 준수로 적어요. |
| `CustomStringConvertible` | 디버깅에 도움이 되는 표현이 있을 때 채택해요. |
| `Codable` | 직렬화 요구가 실제로 있을 때만 채택해요. 미리 넣지 않아요. |

```swift
// Preferred: 조건부 준수
extension Stack: Equatable where Element: Equatable {}
extension Stack: Sendable where Element: Sendable {}
```

## 오류 처리

| 상황 | 처리 방법 |
| --- | --- |
| 쓰는 쪽의 프로그래밍 실수 (범위를 벗어난 인덱스 등) | `precondition`으로 즉시 중단해요. 조건을 문서 주석에 적어요. |
| 값이 없을 수 있는 정상적인 흐름 (빈 스택의 `pop`) | 옵셔널을 돌려줘요. |
| 외부 입력이나 상태 때문에 실패할 수 있는 연산 | `throws`로 알려요. 오류 타입도 함께 공개해요. |

- 성능에 민감한 경로의 내부 검사에는 릴리즈 빌드에서 제거되는 `assert`를 쓰고, 공개 API의 계약 위반에는 `precondition`을 써요.
- 실패를 조용히 삼키지 않아요. 잘못된 입력을 기본값으로 바꿔 돌려주지 않아요.

## 동시성과 Sendable

- 패키지는 Swift 6 언어 모드로 빌드해요. 공개 타입은 동시성 검사를 통과해야 해요.
- 값 타입 자료구조는 요소가 `Sendable`일 때 함께 `Sendable`이 되도록 조건부 준수를 적어요.
- 코어 모듈에는 `@MainActor`를 붙이지 않아요. 액터 격리가 필요한 코드는 UI 타깃에 둬요.
- 내부에 참조 타입 저장소를 쓰면서 `@unchecked Sendable`을 붙일 때는, 안전한 이유를 주석으로 적어요. 이유를 적을 수 없으면 붙이지 않아요.

## 문서 주석

공개 API에는 `///` 문서 주석을 적어요. 저장소의 기존 주석과 같이 `-합니다`체로 적고, 복잡도를 함께 남겨요.

```swift
/// 스택의 맨 위에 요소를 추가합니다.
///
/// - Parameter element: 추가할 요소입니다.
/// - Complexity: 평균 O(1)입니다.
public mutating func push(_ element: Element) {
    self.storage.append(element)
}
```

- 요약은 한 문장으로 적고, 필요한 설명은 빈 줄 뒤에 이어 적어요.
- 시간 복잡도는 모든 공개 연산에 적어요. 상각 복잡도라면 `평균`, `상각`처럼 조건을 밝혀요.
- 추가 메모리를 쓰는 연산은 공간 복잡도도 적어요.
- `precondition`으로 중단되는 조건, 순회 순서, 값 의미론처럼 이름만으로 알 수 없는 계약을 적어요.

## 버전과 호환성

- 버전은 [유의적 버전](https://semver.org/lang/ko/)을 따르고, `SwiftExtension.version` 값과 태그를 함께 맞춰요.
- `0.x` 동안에는 공개 API를 바꿀 수 있어요. 대신 바뀐 내용을 PR 본문과 릴리즈 노트에 반드시 적어요.
- `1.0` 이후에는 공개 API 제거·시그니처 변경을 메이저 버전에서만 해요. 이름을 바꿀 때는 한 번의 마이너 버전 동안 `@available(*, deprecated, renamed:)`로 예전 이름을 남겨요.
- 릴리즈 노트는 `.github/release-drafter.yml`이 PR 라벨로 분류해요. 공개 API를 추가하는 PR에는 `✨ feature` 라벨을 붙여요.

## 공개 API 체크리스트

- [ ] `public`으로 올린 멤버마다 외부에서 필요한 이유를 설명할 수 있어요.
- [ ] 이름이 표준 라이브러리의 같은 의미 이름과 어긋나지 않아요.
- [ ] 복사 후에도 값 의미론이 유지돼요.
- [ ] 채택할 수 있는 표준 프로토콜을 조건부 준수로 적었어요.
- [ ] 실패 상황을 옵셔널·`throws`·`precondition` 중 맞는 방법으로 처리했어요.
- [ ] 문서 주석에 동작과 복잡도를 적었어요.
- [ ] 기존 API를 바꿨다면 호환성 영향을 PR 본문에 적었어요.
